## 二、当前确认的产品目标

1. 主持人可提前录入声音，作为跨场复用的主持人声音档案；支持取消、重录、删除。
2. 嘉宾不需要提前录入。开场或前几轮依次单独讲话，系统提取声音特征并创建本场临时档案。
3. 声音匹配判断是不是同一个人；语义只从本人明确原话补充姓名、职业或项目职责。缺失背景时编号照常使用。
4. 嘉宾人数为1–5，不包括主持人；计划人数不是实际人数的证据，不强制凑齐。
5. 正常路径无需逐个人工确认；异常情况下可更正人物、调整人数或保留未知继续。
6. 本轮以依次单人讲话为条件，不承诺同时发声、噪声严重或极短应答都能识别。不能将 ASR 编号更名后当作注册声纹。
7. 不按固定回答顺序推断人物；跨录音流重新匹配声音，不直接沿用旧 ASR 编号。

## 三、前端用户路径和视觉安排

### 设置 → 主持人声音

独立声音面板沿用微绿白底、翠绿主色、圆角、系统中文字体和现有按钮。包含麦克风图标、真实服务状态、约10秒采集说明、朗读参考、留存说明与同意复选框。勾选前禁用录入；采集中显示进度并提供取消；处理中不允许重复提交；浏览器没有眼镜接口时在面板内明确提示进入 MemoMind App。

保存结果由后端成功响应决定。取消或失败不清除旧档案；若取消时保存已到达服务端，刷新核对最终状态。重录和删除入口只在相应状态可用。

### 模板 → 会前准备 → 开场采集

主题、目标与时长之后是“人物准备”区，显示主持人声音状态、1–5位嘉宾人数和识别方式。可选背景与边界折叠，避免埋住主要入口。流程提示为“主持人声音就绪 → 嘉宾依次介绍 → 正式访谈”。

声纹模式必须检查服务与主持人档案，未就绪明确提示；原模式须由用户自行选择，不静默伪装为声纹识别。

### 开场 → 正式访谈

开场页优先展示人物列表、已建档人数与等待介绍的编号；自动匹配主持人并为新声音建档。已识别人物可展开修改别名。背景提取异步运行，不阻塞转写或声音匹配。

开场不显示追问，不进入正式事实、回应和会后摘要。按钮“开始正式访谈”仅切换阶段；人数不符和未知片段有说明，可补充讲话、调整人数，或明确保留未知开始。进入正式阶段后，仍可在前几轮补齐计划内尚未建档嘉宾。

### 正式访谈 → 异常更正 → 整理

实时转写显示具体人物，完整转写内提供人物更正。更正后撤回相关事实、回应和旧摘要，防止甲的回答记到乙名下。未知、短句和不可靠样本不强行归类。结束先等待已收到的身份请求收尾，最多30秒，随后清理本场声音特征；未完成的片段保留未知。

## 四、后端实现

音频同时进入两条路径：

- 眼镜 Opus → Ogg → 现有流式 ASR → 稳定转写。
- 内存音频环形缓存 → 按同一流时间范围取单人片段 → 声音模型 → 匹配人物。

按 segmentId、streamId、修订号合并。迟到结果不覆盖人工更正或已修订转写。缺少可靠时间范围时保留未知，不能用猜测的音频片段建档。

当前实际接通 `sherpa-onnx 1.13.8` + 中文 `wespeaker_zh_cnceleb_resnet34.onnx`，由服务端 Python CPU 推理。音频通过 stdin 传入，不写原始录音到后端磁盘；Opus/Ogg 用已有 ffmpeg 解码。模型文件每次按配置 SHA-256 核对。

本地质量筛查含有效能量、削波和前后窗口声纹一致性。这不是专门的重叠检测器，仍要求单人发言；不能把筛查结果解释为复杂抢话已解决。预览阈值仅用于开发，不代表真实设备通用阈值。

HTTP 提取适配路径保留，允许未来接入符合协议的服务；火山声纹注册接口并不等于此 embedding 协议，本轮没有混用接口或把通用端点套到 Agent Plan。

## 五、数据和留存

主持人档案按网关凭据命名空间存储，AES-256-GCM 加密并原子替换；加密密钥只在私有环境文件。当前网关访问码不是多租户账户，同一访问码共享同一主持人档案。

本场人物含稳定 participantId、角色、编号、可选别名与背景证据；发言保存人物归属、来源、阶段、时间和修订。声纹向量不返回前端，不进入普通日志、Markdown 或素材索引。

嘉宾声音特征仅驻服务内存，结束删除；未正常结束时最后活动起两小时过期。服务重启不保留嘉宾特征，因此提示结束并新建访谈重新采集，保留已有原话和人物标签。当前不提供跨服务重启无感续访。

## 六、接口

- `GET /api/voice/status`：配置、模型可用性、开发预览及主持人注册状态。
- `POST /api/voice/enroll`：同意后注册或重录主持人声音。
- `POST /api/voice/delete-host`：删除主持人档案及相关临时会话。
- `POST /api/voice/match`：音频片段匹配或依次单人新声音建档。
- `POST /api/voice/end`：清理本场声音特征。
- `POST /api/participant-background`：仅从本人开场原话异步补充身份背景。

沿用现有网关鉴权、来源限制、输入大小和并发保护。前端声音请求按序发送，减少瞬间请求积压；转写仍可先出现。
