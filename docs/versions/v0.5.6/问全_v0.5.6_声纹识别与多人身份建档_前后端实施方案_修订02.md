## 四、v0.5.6 功能需求共识

本轮目标是改善“谁在说话”的归属，并建立前端可实际使用的路径。

- 主持人提前录入声音，保存为可复用的主持人声纹，不要求职业等属性。
- 主持人填写嘉宾人数，数字不包含主持人；首轮范围为1–5位嘉宾。
- 嘉宾开场依次自我介绍，系统自动采集声音，建立本场临时人物档案。
- 姓名、职业或项目职责能从本人介绍中提取就关联；无法提取时用“被访谈者1、2、3”等编号。
- 正常路径不要求主持人逐人手动确认身份。人工纠正是异常处理入口。
- 预设人数只是计划人数，不证明实际人数；人数不一致时提示处理，不强制凑数。
- 默认依次单人发言，不承诺复杂噪声、抢话和重叠讲话识别。

声音用于区分人物，介绍内容用于补充背景。背景缺失不影响人物编号，声音匹配也不代表核验了真实身份。

## 五、前端入口与完整用户路径

### 路径A：首次设置主持人声音

```text
设置 → 主持人声音 → 阅读采集说明并同意
→ 单独讲话录入 → 声音质量检查 → 保存成功
→ 返回访谈准备页
```

界面要求：

- 显示未录入、采集中、处理中、已录入、失败等真实状态。
- 提供开始录入、取消、重新录入和删除入口。
- 采样不足、服务不可用或保存失败时明确提示，不显示虚假成功。
- 取消录入不破坏原有可用档案。
- 声纹服务未配置时说明需要管理员配置；不把ASR编号绑定伪装成声纹注册。

### 路径B：开始一场访谈

```text
选择模板 → 填写主题与目标 → 填写嘉宾人数
→ 查看主持人声音状态 → 开始开场采集
```

准备页必须能发现声音设置入口，不能只在后端增加接口。访谈基本设置、人数和声音准备状态应一起呈现。

### 路径C：嘉宾自动建档

```text
主持人讲话 → 嘉宾依次介绍
→ 自动匹配主持人并区分新声音
→ 展示人物卡与采集进度
→ 可选提取介绍背景，失败则使用编号
→ 开始正式访谈
```

人物卡示例：

| 人物 | 可展示内容 |
| --- | --- |
| 主持人 | 已匹配预录声音 |
| 被访谈者1 | 本人介绍中明确表达的职业或职责 |
| 被访谈者2 | 背景未明确，按编号区分 |

“开始正式访谈”是阶段切换，不是逐人身份审核。开场介绍默认不生成现场追问，不作为项目事实自动归档。

未采集齐时提供明确提示，允许补充介绍、修改人数或处理未知片段，不能让用户陷入无解释的等待。

### 路径D：正式访谈与异常恢复

- 转写显示人物编号或别名，同一人保持相同业务参与者ID。
- 身份尚未确定时文字可以先出现，人物标为待识别。
- 不确定声音不强行标为主持人，也不强行归到已有嘉宾。
- 提供可选人物纠正入口；纠正后重新检查关联事实和问题回应。
- 断线重连时重新匹配声音，不能假设ASR编号仍对应原人物。
- 结束访谈后进入整理页，按既定策略清理临时声音特征，保留原话与人物标签。
- 需要保留档案以续访时，应明确保存时限与删除方式，不能仅用“临时”作含糊说明。

## 六、后端与数据方案

### 1. 并行处理

```text
音频采集
├─ 转写路径：音频 → ASR → 文字与时间范围
└─ 人物路径：单人片段 → 声音特征 → 档案匹配
             ↓
按流ID、片段和时间范围合并
             ↓
带人物归属的发言 → 追问与会后整理
```

身份背景提取异步运行，不作为每段转写和追问的必经串行步骤。

### 2. 三种能力不能混淆

| 能力 | 作用 |
| --- | --- |
| ASR说话人分离 | 提供本次流内声音编号，不保证跨流身份稳定 |
| 声纹提取与匹配 | 对应主持人及本场嘉宾声音档案 |
| 介绍内容提取 | 提取本人明确说出的背景，允许为空 |

真正声纹接口、运行模型和采集格式均需验证。不能把speaker_id重命名为voiceprint后宣称完成声纹识别。

### 3. 数据结构

- 主持人档案：声纹服务标识、特征引用、模型版本和注册状态。
- 本场人物：participantId、host/guest角色、默认编号、可选别名和背景。
- 发言：segmentId、streamId、时间范围、participantId或空值、归属状态及来源。
- 背景证据：本人介绍原话、来源片段和来源人物。
- 访谈：期望嘉宾人数、开场/正式阶段、人物集合。

角色和具体人物分开保存：多位嘉宾都为guest，但participantId不同。改名字不改ID。

### 4. 匹配与归属约束

- 匹配阈值需用标注样本校准，不承诺一个通用阈值适用于所有设备。
- 样本不足或候选接近时保留未知。
- “嗯、对、好”等短应答不用于直接建立或覆盖档案。
- 不用噪声、混叠或低置信片段更新声音模板。
- 过期匹配结果不得覆盖修订后的转写或人工更正。
- 嘉宾2的回答不能自动算作嘉宾1已回应；事实与摘要保留具体人物来源。

### 5. 服务能力检查

实施前确认当前音频编码、分块、时间信息、上游接口权限、声纹注册能力及多人适用范围。不能直接将其他产品端点的参数套用到当前Agent Plan接口。

声纹服务未就绪时，应清楚呈现不可用状态或经用户选择使用原模式；不得静默降级后仍声称使用了声纹识别。
