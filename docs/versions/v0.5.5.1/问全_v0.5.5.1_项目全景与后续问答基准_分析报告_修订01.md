## 2. 产品定位和完整流程

问全是有准备、有主线的现场访谈助手。重点场景是一位主持人与一位嘉宾的中文访谈。手机承担准备、交互、记录与更正，眼镜承担单条建议展示，云端承担 ASR 和文本模型调用。

完整流程为：选择模板 → 编辑目标与主线 → 确认准备和录音条件 → 前台采集 → 稳定转写入库 → 判断主持人/嘉宾角色 → 提取有出处的信息并判断问答关系 → 更新候选建议 → 主持人选择、已问、稍后或略过 → 主动结束 → 整场归纳 → 编辑摘要和导出。

六个新建模板均使用分析协议 v2，不预填嘉宾回答：

| 模板 | 默认分钟 | 主线 |
| --- | ---: | --- |
| AIdol 选手快访 | 7 | 项目与演示、痛点与起因、方案与取舍、困难与攻克、验证与下一步 |
| 人物经历 | 30 | 起因、关键选择、最大困难、回看与建议 |
| 用户研究 | 25 | 触发与目标、实际过程、阻力与替代、结果与取舍 |
| 需求澄清 | 40 | 真实流程、规则与例外、第一版范围、资料与系统、验收与推进 |
| 项目复盘 | 30 | 目标与结果、关键节点、有效与受阻、下次怎么做 |
| 专业观点 | 30 | 问题与概念、判断与依据、案例与分歧、边界与行动 |

旧 FDE、旧研究和自定义数据模型仍保留兼容路径，但不应与首页六个新模板混为一谈。历史剧本和固定 demo 仍存在于资料或兼容代码，当前首页已移除旧体验示例入口。

时长是节奏建议，不会到时自动结束。AIdol 的 5–8 分钟是使用建议，默认保存为 7 分钟。会中计时由渲染时计算；不据此承诺独立每秒刷新的时钟。

## 3. 各端职责和依赖

```text
MemoMind 眼镜麦克风
  → MemoMind App / GM Web SDK audio.openCapture
  → 手机插件增量 Ogg Opus 封装
  → 网关 WSS /api/asr/stream
  → 火山 Agent Plan 豆包流式 ASR
  → 手机稳定分句、角色判断、批次分析
  → 网关 HTTPS 模型接口
  → 结构与逐字引用校验
  → 手机本地保存、单题画布
  → GM Web Bridge v2 → 眼镜图像显示
```

手机页面是原生 JavaScript 模块、HTML 和 CSS；没有 React/Vue 等前端框架。服务端使用 Node.js 原生 HTTP，package.json 要求 Node >=22，唯一直接 npm 依赖是 ws，锁定结果为 8.22.0。

默认网关为 `https://cx.kevinxu.cn/wenquan`。默认文本模型配置示例是火山 Agent Plan `deepseek-v4.1-flash`，ASR 为豆包流式语音识别 2.0 的套餐专用接口。具体运行模型由服务器环境变量决定，不能仅凭示例证明线上当前配置。

App 内置 ASR 没有被这个项目作为公开插件接口调用。项目使用公开音频采集接口，再走独立云端 ASR。旧文档中的 JoyMaas 是曾用文本模型和可选配置，不代表当前默认路由。

## 5. 数据、状态与一致性

顶层 state 使用 schema=1，包含 topics、当前主题/会话索引及 settings。主题可有多次 session；会话保存提纲 items、转写 segments、陈述 claims、问题 questions、actions、events、revision、录音暂停与结束状态。

v2 额外保存当前章节、章节状态、嘉宾背景和资料来源、边界、角色绑定、章节摘要及整场归纳。片段保留 original、当前 text、角色、输入来源、修订号和编辑历史。ASR 片段还保留采集流、时间、说话人编号等元数据。

章节状态：未展开、正在展开、已有内容、待补充、主持人确认结束。问题状态：候选、当前展示、已问待回应、已回应、稍后、跳过、被新信息替代。这两组状态分别管理。

关键规则：展示不等于已问，已问不等于已回应，已回应不等于章节完整。模型不能自行关闭章节或结束访谈。主持人可切换主线、标记聊完、调整顺序或记录自拟问题。

更正文本或角色会保留历史并撤回派生分析；源片段、会话、revision、取消状态变化后，旧结果不提交。v2 实时上下文主要来自当前会话，不能把旧 v1 的跨会历史窗口规则扩大为 v2 自动继承全部历史问答。

## 6. 语音、说话人与模型行为

### 6.1 采集与稳定转写

原生采集调用 gm.audio.openCapture，200 ms 分块，frontBalanced，开启降噪，每次最长 60 分钟。Opus 增量转为 Ogg 后走 WSS，不先缓存整场录音再上传。

中间结果只预览；稳定分句或最终结果进入记录。相同分句按时间范围去重，缺少有效时间时采用无时间分句路径并标明限制。后续稳定修订会显式更正并撤回旧分析。

离开前台、页面隐藏、断连或主动取消会停止采集。正常停止等待尾包；后台取消可能失去未稳定尾句。遇到网络积压、丢帧或超时明确失败，不自动套用 demo。队列超过 150 段会停止录音并保留已识别文字。

文件导入支持 Ogg/WAV/MP3/M4A/MP4/WebM/FLAC 容器，最大 5 MiB；回放解码后最多 120 秒，以 16 kHz 单声道 PCM、200 ms 节奏发送。实际可解码格式还取决于 WebView。云端主路径不依赖 ffmpeg；旧 HTTP 文件接口属于另一条兼容路径。

### 6.2 角色判断的真实边界

ASR speaker_id 只代表本次采集中的声音编号。前端采用 `streamId:speakerId`，不同采集流不自动关联身份。文本模型结合自我介绍与问答语境判断 host/guest；角色上下文取最近 32 段，服务端另有 40000 字符总限。

仅采用模型自报 confidence>=0.9 且通过引用校验的判断；这不是准确率达到 90% 的证明。冲突、低置信或资料不足保留 unknown，人工角色优先。支持声音编号到角色绑定以及片段更正。

该版本没有声音特征向量模型、主持人预录声纹、注册声纹库、跨会身份认证或多人实名档案。多人声音编号与主持人/嘉宾二元业务角色，也不等于完整多人访谈产品。

### 6.3 实时建议

稳定语音按最多 16 段、24000 字符组成分析批次；总上下文预算约 40000 字符，结合近期最多 80 段和每章早期/近期陈述出处。原话在本地完整保存，不等于全部内容每次都发给模型。

每次输出 0–3 条候选，区分深挖、补充、转场。深挖必须引用嘉宾原话；提纲建议明确采用 outline 依据。手机保留完整问题，眼镜 hint 最多 28 字。结构、主线 ID、片段 ID、角色、连续逐字引文和问答轮次均校验。

确认提纲后无需任何语音即可本地生成第一条主线建议。回答后的有效模型建议优先；已问时保留待答提醒。没有新语音不会按静默时长自动换题。主线问题已回应且没有其他候选时，可建议下一条主线。略过/稍后不是已答，最终收尾也不自动结束。

新候选通常保留当前阅读题，已回答或过时项可撤下。60 秒未复核提示在分析应用时检查，不是独立计时器。语义重复、是否值得追问和引用是否真正支撑概括仍依赖模型及人工判断；精确字符串校验不能证明这些语义正确。

上游采用 OpenAI 兼容 chat/completions、temperature=0.2、JSON 输出；默认 max_tokens=2500。单次上游 35 秒超时。配置 repair 后结构/引用校验失败最多再请求一次；草稿和被拒绝结果不写成正式记录。

### 6.4 会后归纳

结束后读取整场转写，输出最多 5 点整场核心、每章最多 8 点，以及待补问。校验器允许最多 12 条补问，提示词进一步要求最多保留 3 条值得问的内容；应区分软约束与程序硬上限。

上限为 1500 段、240000 字符；长内容以约 18000 字符分块先归纳，再合并有来源笔记并重新校验。超限显式失败。每个要点必须有嘉宾连续原话，不能把主持人假设或 unknown 作为嘉宾结论。

用户可编辑章节摘要，重新归纳保留人工摘要；更正源转写会使旧归纳失效。完整 Markdown 包含主题内历次会话、原话和问题；素材索引主要针对当前会话，包含来源位置。采集段时间不是外部视频时间码，项目没有完整原始音频归档和剪辑系统。

## 7. 存储与眼镜显示

存储根键 `wenquan.interviews.v1`。宿主环境走 gm.storage，普通浏览器预览走 localStorage。整个 JSON 按最多 8000 UTF-16 单元切块；每块最坏编码约低于 48 KB，绕开宿主单项 64 KB 上限。

采用两组快照：写非活动组全部分块，最后切换索引；索引含块数、长度与校验值。失败不以空记录覆盖，提交响应丢失后重读索引。旧单项数据在首次成功保存时迁移。保存队列串行，失败持续提示重试或导出。双组快照不是无限容量，也没有实现读坏当前组时自动回退另一组的完整灾备流程。

眼镜画面为 600×350，GRAY_4，每帧拆成两块 600×175。两块均返回 presented=true 才记显示确认；暂停/结束调用 closePage 并要求 closed=true。排队策略偏向最后一次显示意图。

画面包含建议类型、章节位置和名称、单条短问句、下一主线以及“建议·自由选择”。无问题但已开始时可显示低亮度待机。字号主规格 44px，根据字宽换行。镜片发光颜色由设备决定，网页绿色模拟不是光学验收。

送达指标保留最近 200 条，测量 ASR 稳定结果到双图块确认的间隔，不含真实说话结束至 ASR 稳定的耗时，也不能证明佩戴者实际看到了内容。

## 8. API、鉴权和部署结构

| 方法和路径 | 用途 |
| --- | --- |
| GET /api/health | 功能与模型/ASR 配置声明，配置不等于调用成功 |
| POST /api/checklist | 根据目标生成待审核主线草案 |
| POST /api/analyze | v1 或 v2 实时分析 |
| POST /api/identify-speakers | 根据文本语境识别 host/guest |
| POST /api/summarize | 整场归纳 |
| POST /api/transcribe | HTTP 文件转写兼容路径 |
| WS /api/asr/stream | 手机与网关的流式语音 |

文本接口兼容完整 JSON 和 application/x-ndjson。增量包括 start、delta、reset、progress、result/error；正式结果校验后才提交。手机普通接口超时 90 秒，归纳 600 秒；与每次上游请求 35 秒分层管理。

HTTP /api/ 使用 Bearer 网关访问码；WS 首条 start 消息带访问码，通过后才连接上游，不放 URL。配置访问码至少 32 字符，采用 SHA-256 后 timingSafeEqual 比较。生产入口对外监听时要求访问码。源码 HTTP 并发上限 3，WS 同时连接上限 2，均为进程级控制，不是多租户配额系统。

生产资料描述 Docker + Caddy，公网 /wenquan 路由转到服务器回环 8788，再到容器 8787。容器非 root、只读文件系统、限制资源。Studio 开发服务监听 127.0.0.1:8790，明确取消设备访问码，仅用于本地开发。

项目没有完整账号体系、团队权限、云端访谈数据库或跨设备自动同步。原始音频不由项目后端主动落盘，但音频和文字会发送上游；宿主日志、文件选择副本和上游留存不能由本工程“不写盘”推断为零留存。

0.5.5.1 README 明确记录经所有者授权公开共享网关凭证组合包；源码默认访问码仍为空，上游模型和 ASR Key 不应包含在手机包。这是分发属性的记录，本轮没有显示、使用或轮换包内凭证。

## 9. 打包、归档和脚本

scripts/build.mjs 依赖相邻 `../plugin-open-platform` 中的官方 PhoneSDK 打包器和 Web SDK，复制 web 到 dist，按本地私密连接配置注入访问码，生成 MMPKG，并更新 PhoneSDK 示例和 dist 镜像。仅下载本仓库不等于具备全部构建依赖；当前 Windows SDK 所在路径也不同于脚本原有相邻目录假设。

仓库 `.command` 启动器使用 zsh、open -a 和 macOS 应用名称，部分探针使用 say/ffmpeg，不能直接当作 Windows 启动说明。Windows Studio 路径仍参考工作区 AGENTS.md，但本轮未启动 Studio 或导入包。

scripts/check.mjs 是 JS 语法检查；tests 使用 node:test。benchmark 和 probe/verify 系列多数会启动本机服务、真实请求模型或 ASR 并写 evidence，部分固定历史版本断言，例如 verify-interview-0.4.mjs 要求 health=0.4.0，不能直接用于当前网关判定失败。本轮均未执行。

history/mobile 保存 0.2.5、0.3.0、0.4.0 的脱敏手机发布文件，并有 provenance 哈希记录。它们没有相应完整后端、测试与 SDK，不是当前运行入口。design/glasses.html 复用实际绘图函数，属于设计预览，不是另一套眼镜业务实现。
