## 确认的问题与修复建议

### F01 · P1 · 准备页离开时静默丢失输入

复现：进入专业观点模板；标题改成“UI审计草稿保持测试-专业观点”；点击底栏“访谈”；列表仍是原题“把一个专业问题讲明白”；再点“记录”，也是原题。离开前没有保存或丢弃提醒。

影响：用户可能丢失会前准备，而误以为已经保存。

定位：web/app.js 的 data-view 路径只调用 setView；setView 仅 snapshotDraft，未 capturePreparation。后者才把准备表单写入主题/会话。

方案：导航前统一保存准备草稿，保存失败留在原页并显示可恢复错误；表单显示“已保存/保存中”。保存草稿不要等价于确认主线。

验收：修改主题、目标和主线，切换到首页/记录/设置再返回均保留；失败时有明确反馈。

### F02 · P1 · 开场文本提交成功却不刷新，导致重复保存

复现：AIdol 模板保持声音档案模式，点“文本演练”；展开文本输入并填写测试句；点“保存并分析”，原输入和 0 段计数仍留在屏幕；再次点击；结束后结果页变为 2 段对话。

定位：web/app.js 的 analyze action 先 addSegment、清空 draft、save，再调用 analyzeSegment；analyzeSegmentImpl 在 opening 阶段直接 return，没有 render。

方案：保存完成立即刷新列表、清空输入并显示“已保存，开场内容暂不参与追问分析”；提交期间禁用按钮并保护同一次提交。不要把开场不分析表现为无响应。

验收：开场提交一次只产生一段，页面立即更新；连续点击不会重复写入。

### F03 · P1 · 手动选择章节与当前建议、眼镜章节不一致

复现：原角色模式的正式访谈，将第一章“起因”放入稍后；第二章点“已问”；展开主线，点击第一章“聊这一章”。主线列表显示第一章“正在展开”，但手机建议和眼镜显示第三章“最大困难”（3/4）。

定位：web/interview.js 的 setChapter 只改变当前章节并清空当前候选；ensureInterviewSuggestion 将 deferred 视为已消费，继续寻找后面的未消费章节。

方案：显式选章时优先恢复该章可用或稍后问题。没有问题时显示该章空态并允许补记，不自动跳到别章。currentChapter、展示问题和 HUD 使用一致的选中章节来源。

验收：选择第一章后，章节标记、手机问题和眼镜均属于第一章。

### F04 · P1 · 文本演练沿用声音建档前置流程

复现：声音档案模式下点“文本演练”，仍进入“开场采集”，要求主持人/嘉宾依次讲话，0/1 位嘉宾；点“开始正式访谈”只出现人数不符提示。用户必须自己发现并切换到原角色模式，或进入人数调整路径。

方案：文本演练使用独立的文本人物/角色设置，直接进入可输入的演练工作区；若仍要声音流程，点击前说明依赖并提供清楚的文本替代入口。

验收：不录声音也能从文本演练顺畅进入正式文本问答，且不会被要求建立声音档案。

### F05 · P2 · 同名折叠区状态串联

复现：结果页只展开第一章“编辑本章摘要”，输入并保存；保存后其他章节的“编辑本章摘要”也一起展开，页面长度明显增加。

定位：web/app.js:229、233 使用 summary.textContent 保存/恢复 details 状态。同名 summary 相互混淆。

方案：每个折叠区使用稳定且唯一的键，例如 sessionId + chapterId + panelType；不要使用展示文案做标识。

验收：保存第一章只保留第一章编辑区展开，其他章节状态不变。

### F06 · P2 · 新页面继承旧滚动位置，关键反馈离开视野

复现：滚动到首页较下面的用户研究、需求澄清、项目复盘模板后点击使用，准备页直接落在声音准备/主线区域，看不到主题和目标；在会中下方结束访谈，结果页也停在章节中下部，看不到顶部归纳失败原因。

方案：统一路由切换接口，新建/结束时重置实际滚动容器到顶部，或定位本次操作结果。区分“刷新当前页”和“进入新页面”，前者保留位置、后者显式定位。

验收：列表任意位置进入新准备页、结束进入结果页时都先看到标题和状态。

### F07 · P2 · 必填标记与行为不一致

复现：人物经历模板清空带星号的访谈主题后点开始，未阻止提交，自动生成“未命名主题”，随后才报 ASR 未配置。

定位：capturePreparation 将空标题转成“未命名主题”；准备 form 使用 novalidate。

方案：确定产品规则。标题必填则在开始前定位字段并解释；允许空标题则取消星号，并明确自动命名行为。

验收：字段标记、开始按钮、错误定位和保存规则一致。

### F08 · P2 · 识别模式切换后，流程文案和主按钮未更新

复现：将人物识别方式改为“原模式 · 仅区分访谈角色”，页面仍显示“先认声音，再聊故事”、主持人声音就绪/嘉宾介绍步骤，按钮仍为“开始开场采集”。实际点文本演练后却直接进入正式访谈。

方案：选择器 change 时同步更新说明、人物输入和开始按钮；原角色模式弱化或隐藏声音建档步骤。

验收：选择原模式后立即显示对应流程；按钮准确描述实际行为。

### F09 · P1 · 服务设置文案错误承诺可直接使用

复现：设置页地址是 http://127.0.0.1:8798，检测显示“文本模型未配置 · 语音转写未配置”，但静态说明仍说“密钥只保存在云端”“无需 Mac 开机”“个人安装包已预置云端连接，可直接开始访谈”。

定位：web/index.html 的设置说明写死为云端场景。

方案：按本机/云端地址及检测能力生成说明；未就绪时明确列出缺项。准备页开始前检测必需能力，并提供修复入口。

验收：本机未配置时不出现“已预置云端、可直接开始”的承诺。

### F10 · P2 · 二级声音设置的返回层级错误

复现：从底栏设置打开分析设置，进入主持人声音，点“返回”，直接回到结果页，分析设置消失。

定位：voice-settings action 先 close 分析设置；voice-close 只 close 声音弹窗，没有恢复调用方。

方案：记录声音设置的来源；返回时恢复来源页面/弹窗、未提交输入和滚动位置。

验收：分析设置→声音→返回，仍处于分析设置，表单内容保留。

### F11 · P2 · 录音与暂停状态文案相互矛盾

复现：文本演练未录音时标题是“正在听到”；暂停后仍保留“尚未开始录音，可直接输入文本演练”，但输入和提交已禁用。

方案：统一录音/文本/暂停/失败状态模型。分别显示“文本演练”“已暂停，继续后可输入”“录音启动失败”；状态说明与控件可用性同源。

验收：每种状态下说明、按钮、输入禁用状态一致。

### F12 · P2 · 结果页错误缺少可行动的分类

复现：开场测试文本已保存两段，结束后显示“访谈原话为空或超出处理范围，请拆分访谈”。用户无法区分没有正式内容、角色未识别、未配置模型、长度超限等情况。

说明：这条提示确实出现；本轮没有证明触发它的全部后端原因。

方案：前端先区分零段、只有开场段、无可归纳嘉宾段、服务缺项等状态；展示准确数量、原因和一个直接修复动作。

验收：少量开场文本不提示用户“拆分访谈”；缺模型时指向服务设置。

## 设计风险与环境待核实项（不混同已确认的业务 bug）

### R01 · P2 · 横屏可用内容高度不足

实际横屏结果页中，页头、标题、操作栏与底部导航占据大量高度，几乎看不到章节内容。设置弹窗只露出上半部分，检测与保存需滚动查找。

建议：短高度布局压缩页头，次要操作收进菜单；弹窗将关键操作置于固定底部，并确保正文独立滚动。验证手机键盘弹出后的短高度场景。

### R02 · P2 · Studio 眼镜预览右侧裁切

在本轮竖屏正式访谈可观察到 HUD 右侧章节和底部“建议 · 自由选择”靠右显示不全。只能确认 Studio 当前预览问题，不能据此断言真实眼镜输出越界。

建议：先验证预览容器是否完整缩放 600×350、是否可横向滚动，再检查原始画面与真实眼镜。不要直接缩小全部文字掩盖预览容器问题。

### R03 · P2 · 已问缺少直接撤销入口

实际点击已问后进入等待回答，已问和稍后都禁用，未看到直接撤销操作。误触后需深入其他入口处理。

建议：短暂提供撤销，并在问题记录中允许明确纠正；不以强制进入下一题替代纠正。

## 本轮正常工作的路径

- 六模板入口均能进入对应准备表单，预置时长与章节内容匹配。
- 暂停会保留已输入的文本草稿，继续后可恢复输入。
- 正式访谈“稍后”能切到后续主线并同步眼镜；“已问”能切到等待回答并同步。
- 手动摘要保存后正文出现测试摘要。
- 提纲追加两行后生成两章，原章节未被替换。
- Markdown 导出实际落盘：C:/Users/Cccong/Downloads/UI审计测试｜请忽略｜1018_访谈记录.md。
- 服务检测能显示后端版本和模型/语音缺项。
